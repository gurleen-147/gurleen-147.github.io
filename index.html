How it was built

  1. VLANs, SVIs and inter-VLAN routing on the HQ layer 3 switch
  2. DHCP pools for each VLAN
  3. WAN links and OSPF, including a default route to the ISP
  4. Branch VLAN with DHCP relay back to HQ
  5. NAT/PAT so every site reaches the internet through the HQ router
  6. Security: guest isolation, SSH with local AAA, management limited to IT
  7. Diagram, IP table and configs written up and published to GitHub

Security I added on my own

  • The original plan had no security. I noticed any PC could reach device configuration, so I added it after the network worked.
  • An extended ACL keeps Guest away from Sales and IT while still allowing internet access.
  • SSH with local AAA login on the managed devices, and the VTY lines accept connections from the IT VLAN only.

Troubleshooting case

The branch PCs that never got an IP address

After the branch router was configured, the branch PCs could not get an address from the HQ DHCP pools. I worked through it layer by layer.

Ruled out
1. RoutingOSPF was up and both sites could reach each other.
Ruled out
2. DHCP setupThe pool and the relay address on the branch router were correct.
Root cause
3. Layer 2The branch switch port facing the router had never been assigned to the branch VLAN.

Fix. I assigned the port to VLAN 40, and the PCs received their addresses immediately.

Lesson. Correct Layer 3 configuration does not help while Layer 2 is broken underneath it. Now I check both, in order.
